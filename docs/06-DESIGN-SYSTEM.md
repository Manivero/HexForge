# HexForge — Design System & Design Tokens

Референсы: Linear (плотность и типографика), Raycast (Command Palette,
скорость), Figma (граф/canvas взаимодействия), Burp Suite Pro / IDA Pro
(профессиональная, "инструментальная" эстетика — не consumer app).

Источник истины — код: `tailwind.config.ts` и `src/styles/globals.css`
(оба файла созданы в проекте, см. `07-PROJECT-SCAFFOLD.md`). Ниже —
обоснование значений, не дублирование кода.

## 1. Цвет

Тёмная тема — основная (default), светлая — вторичная, обе через CSS custom
properties (не через Tailwind `dark:` варианты напрямую в компонентах —
компоненты всегда ссылаются на семантические токены `bg-surface-1`,
`text-primary` и т.д., что делает тему переключаемой без перекомпиляции
классов).

- Нейтральная шкала — 12 ступеней (`--neutral-1` … `--neutral-12`), холодный
  (slightly blue-shifted) серый, а не чистый серый — стандартная практика
  Linear/Radix для снижения "плоскости" плотного UI.
- Акцентный цвет — один (`--accent-9` как базовый), используется скупо:
  активные состояния, фокус, выделенный узел графа. Никаких вторичных
  "декоративных" акцентов.
- Семантические статусы узлов графа: `--status-idle` (neutral), `--status-running`
  (accent, с pulse-анимацией опасности overuse — только opacity, не цвет-моргание),
  `--status-error` (red-9), `--status-stale` (amber-9, приглушённый).
- Контраст: все пары текст/фон проверены на WCAG AA (4.5:1 для обычного текста,
  3:1 для крупного/UI-элементов) в обеих темах — это NFR-7, не опция.

## 2. Типографика

- Основной UI-шрифт: `Inter` (variable font) — плотный, нейтральный, широко
  протестирован на мелких кеглях, как в Linear.
- Моноширинный шрифт (hex viewer, код параметров, hash-выводы): `JetBrains Mono`
  — осознанный выбор бренда-соседа по эстетике (JetBrains упомянут в ROLE
  как референс инженерной культуры) и объективно один из лучших моно-шрифтов
  для различения `0/O`, `1/l/I` — критично для hex/crypto контекста.
- Шкала кеглей — компактная и дискретная, без "лишних" промежуточных
  размеров: `11px / 12px / 13px / 14px / 16px / 20px / 24px`. Плотный UI
  (метафора "IDA Pro", не "маркетинговый сайт") не нуждается в 8-ступенчатой
  шкале с 32/40/48px заголовками.

## 3. Пространство и плотность

- База — 4px grid (`--space-1 = 4px` … `--space-16 = 64px`), без "магических"
  нестандартных отступов в компонентах.
- Плотность по умолчанию — "compact": высота строки списка/таблицы 28px,
  высота инпута 32px. Это соответствует ожиданиям профессионального
  инструмента с большим количеством данных на экране (в отличие от
  consumer-приложений с 44-48px тач-таргетами).

## 4. Радиусы и тени

- Радиусы — три уровня: `--radius-sm (4px)` для мелких элементов (badges,
  inline-controls), `--radius-md (6px)` для карточек/панелей/узлов графа,
  `--radius-lg (10px)` для модалок (Command Palette, диалоги). Никаких
  `rounded-full` кнопок и никакого "мыльного" iOS-стиля — острые
  профессиональные формы.
- Тени — только функциональные, обозначающие elevation ровно двух уровней:
  `--shadow-panel` (плоские панели над канвасом) и `--shadow-overlay`
  (модалки/палитра, которые перекрывают весь остальной UI). Никаких
  декоративных теней на кнопках/инпутах.

## 5. Анимация

Жёсткое ограничение из ROLE соблюдается буквально в токенах:

```
--motion-duration-fast: 150ms;
--motion-duration-base: 200ms;
--motion-ease-out: cubic-bezier(0.16, 1, 0.3, 1);
```

Используется исключительно для: (1) появления/исчезновения Command Palette
и модалок, (2) pan/zoom канваса графа (инерция), (3) индикации прогресса
(progress bar, node status pulse). Никаких анимаций "просто для красоты"
(hover-scale на кнопках, decorative parallax и т.п.) — противоречит
директиве "минималистичный, сфокусированный на данных".

## 6. Иконография

- Один набор — `lucide-react` (открытый, консистентный stroke-width 1.5-2px,
  уже принят как стандарт в shadcn/ui экосистеме, что соответствует
  директиве "компоненты в стиле shadcn/ui"). Никаких смешанных icon-sets.

## 7. Компонентная база

- Radix UI Primitives (`@radix-ui/react-dialog`, `-dropdown-menu`, `-tooltip`,
  `-context-menu`, `-tabs`, `-scroll-area`) — обеспечивают accessibility
  (focus trap, ARIA) бесплатно, что закрывает NFR-7 без ручной работы.
- Визуальный слой — компоненты в стиле shadcn/ui, физически скопированные в
  `src/components/ui/*` (не npm-зависимость), как явно указано в ROLE —
  это даёт полный контроль над стилями без forking стороннего пакета.

## 8. Grid / Canvas графа

- Канвас узлов рендерится на фоне точечной сетки (`--grid-dot` цвет,
  `24px` шаг) — визуальный якорь масштаба, как в Figma/tldraw, без которого
  pan/zoom干 DAG теряет пространственную ориентацию у пользователя.
- Рёбра — кривые Безье (не прямые линии и не ортогональные "conduit"-линии
  как в старых enterprise BPM-редакторах) — визуально яснее показывают
  направление потока данных при большом количестве пересечений.
