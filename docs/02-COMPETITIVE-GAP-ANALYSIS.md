# HexForge vs CyberChef — Competitive Gap Analysis

Принцип документа: каждая структурная слабость CyberChef разбирается до
первопричины (не симптома), и первопричина закрывается архитектурным решением
HexForge — не косметической правкой.

| # | Слабость CyberChef | Первопричина | Ответ HexForge | Архитектурный механизм |
|---|---|---|---|---|
| 1 | Зависает/крашится на файлах от ~500МБ–1ГБ | Всё выполняется в браузерной вкладке: единый JS heap, DOM как часть memory pressure, нет истинного стриминга | Работа с файлами до 32ГБ без деградации | Rust-ядро вне DOM, чтение чанками по 64МБ в отдельных тредах, zero-copy slicing (`04-RUST-CORE-ARCHITECTURE`) |
| 2 | Recipe — линейный список операций сверху вниз | Модель данных CyberChef — `Operation[]`, применяемый последовательно к одному буферу | Recipe — DAG узлов с ветвлением/слиянием | Node Graph Workspace (FR-1.x), состояние — граф, не массив |
| 3 | Нельзя сравнить два варианта декодирования side-by-side | Нет понятия "ветка"; один буфер — одно состояние | Параллельные ветки из одного источника + diff-узел | Fork/Merge примитивы графа + byte-level diff view |
| 4 | JS single-threaded — тяжёлые операции (напр. большие regex, крипто) фризят вкладку | Web Workers используются частично и непоследовательно, message-passing overhead высок | Гарантированно неблокирующий UI при операциях >16ms | Каждая `Transform` выполняется в Rust thread pool (Tokio blocking pool / rayon), IPC асинхронный |
| 5 | Добавление своей операции требует форка репозитория и пересборки всего проекта | Операции — часть монолитного JS-бандла | Плагины — динамически загружаемые подписанные WASM-модули | WASM Component Model + Ed25519-подпись + capability-based sandboxing (FR-6.x) |
| 6 | История — простой undo/redo стек, теряется при сложных экспериментах | История моделирует линию времени, а не дерево экспериментов | History = state DAG, время-путешествие с ветвлением из любой точки | Time-Travel Debugging модель (FR-4.x), каждый снапшот воспроизводим и адресуем |
| 7 | Нет автоопределения формата — пользователь вручную перебирает операции ("Magic" в CyberChef ограничен и неточен) | Эвристика "Magic" — плоский список правил, не композиционный поиск | "Magic Wand" — поиск по графу возможных декодирований с ранжированием по энтропии/сигнатурам | Композиционный solver поверх реестра `Transform` + entropy/magic-bytes скоринг |
| 8 | Нет строгой типизации на границе UI/логики — баги "operation вернула не то, что ожидал UI" | Всё на JS/JSON без статической проверки на IPC-подобной границе | Полная типобезопасность фронт/бек | TypeScript strict + Rust, единый источник правды в IPC-контракте, codegen там где возможно (`05-IPC-CONTRACT`) |
| 9 | UI — веб-страница с заметным DOM-рендер-лагом при больших выводах (напр. hex dump мегабайтного буфера) | Виртуализация списков сделана точечно, не системно | Виртуализация как системное требование для любого списка/грида/hex-view | Windowed rendering по умолчанию в дизайн-системе, hex-viewer рендерит только видимый диапазон |
| 10 | Нет CLI/автоматизации — CyberChef "For Server" существует, но это отдельный незрелый проект | Веб-архитектура плохо переносится в headless-контекст | Единое Rust-ядро работает и в GUI, и в CLI без дублирования логики | `hexforge-core` не знает о Tauri/React; CLI — тонкий бинарь поверх того же крейта |
| 11 | Нет проверяемой воспроизводимости результата (версия операции нигде не фиксируется) | Recipe JSON не содержит версий операций | Каждый снапшот фиксирует версию операции и хэш входа | Reproducible state snapshot (FR-4.2) |
| 12 | Расширяемость ограничена доверием ко всему codebase — нет модели минимальных привилегий | Все операции выполняются с одинаковыми (полными) правами в контексте вкладки | Explicit per-plugin capability grants, дефолт — deny-all | Изолированный процесс/sandbox с минимальными привилегиями (Security Mandates) |
| 13 | Взаимодействие с интерфейсом требует мыши (drag-and-drop операций в список) как основной паттерн | UX спроектирован вокруг drag-and-drop списка | Command Palette как first-class интерфейс, drag-and-drop — вторичная опция для графа | ⌘K везде, полная keyboard-first навигация (NFR-7) |
| 14 | Нет нативного ощущения — выглядит и ощущается как веб-страница 2016 года | Bootstrap-подобный UI, отсутствие единой дизайн-системы | Дизайн уровня Linear/Raycast/Figma, единая токен-система | Design tokens + Radix + Tailwind, анимации 150-200ms ease-out (`06-DESIGN-SYSTEM`) |

## Итог
CyberChef оптимизирован под "работает в любом браузере без установки" — это его
осевая (и оправданная в 2016 году) ставка, и одновременно источник всех 14
ограничений выше. HexForge меняет ось на "нативный проверяемый инструмент для
профессионала" и получает многопоточность, честную работу с памятью, песочницу
для расширений и граф вместо списка бесплатно — как следствие смены платформы,
а не как набор точечных патчей поверх веб-модели.
