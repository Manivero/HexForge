# HexForge — Product Requirements Document

Версия: 0.1.0 (MVP scope)
Статус: Approved for implementation

## 1. Продуктовое видение

HexForge — нативное desktop-приложение для трансформации, декодирования и анализа
произвольных данных (байтовых потоков, текста, сетевых артефактов, бинарных
форматов). Продукт занимает нишу CyberChef, но убирает три структурных
ограничения оригинала: **браузерный рантайм** (лимит памяти, отсутствие
настоящей многопоточности, JS single-thread), **линейную модель
recipe-as-list** (невозможность ветвления/слияния потоков) и **непрозрачную
модель расширения** (baked-in операции, а не подписанные динамически
загружаемые модули).

Продукт не является веб-приложением. Никакого браузерного рендеринга бизнес-логики.
Вся трансформация данных выполняется в Rust-ядре; React отвечает исключительно
за представление состояния.

## 2. Целевые пользователи и Jobs-to-be-Done

| Персона | JTBD |
|---|---|
| Malware Analyst | Раскрутить многослойный обфусцированный payload (base64→gzip→xor→pe), не теряя промежуточные состояния |
| DFIR-специалист | Обработать дамп памяти/диска в десятки ГБ без падения инструмента и без полной загрузки в RAM |
| CTF-игрок | Быстро перебрать эвристики (auto-detect encoding) с минимальным трением UI, всё с клавиатуры |
| Security Researcher | Написать/подключить собственную операцию как плагин, не пересобирая всё приложение |
| Reverse Engineer | Визуально сравнить несколько параллельных путей трансформации одного и того же входа (diff веток графа) |

## 3. Функциональные требования

### 3.1 Node Graph Workspace (ядро UX)
- FR-1.1: Рабочая область — направленный ациклический граф (DAG) узлов, а не список.
- FR-1.2: Узел = один Operation Node с 1..N входами и 1..N выходами (напр. `Split` даёт 2+ выхода, `Merge`/`XOR` принимает 2+ входа).
- FR-1.3: Пользователь может создать ветвление (fork) из любого выхода в несколько независимых цепочек.
- FR-1.4: Пользователь может слить (merge) несколько веток через бинарные/N-арные операции (concat, xor, diff, zip).
- FR-1.5: Каждое изменение графа или содержимого узла порождает новый snapshot состояния (см. FR-4).
- FR-1.6: Мгновенный (<16ms реакция UI) предпросмотр вывода активного узла без ожидания пересчёта всего графа ниже по потоку (lazy evaluation, только затронутая ветка инвалидируется).

### 3.2 Command Palette (⌘K) — первичный интерфейс
- FR-2.1: Глобальный вызов по ⌘K / Ctrl+K из любого экрана приложения.
- FR-2.2: Fuzzy-поиск по: операциям (200+), недавним recipe, файлам ввода, командам приложения (open file, export recipe, toggle theme, split node...).
- FR-2.3: Добавление операции в граф прямо из палитры — создаёт узел, подключённый к текущему выделенному узлу (или создаёт корень, если граф пуст).
- FR-2.4: Палитра поддерживает inline-аргументы через "/" синтаксис (напр. `base64 decode --alphabet url-safe`).
- FR-2.5: Вся навигация приложения (переключение вкладок, открытие панелей) дублируется в палитре — панели вторичны, палитра first-class.

### 3.3 Операции (Operations) — MVP набор
Категории и минимальный состав для MVP (полный список — по мере роста; архитектура
обязана поддерживать 400+ операций без изменения ядра, см. `04-RUST-CORE-ARCHITECTURE`):

| Категория | Операции MVP |
|---|---|
| Encoding | Base64 (std/url-safe/custom alphabet), Base32, Base58, Hex, URL encode/decode, HTML entities, Quoted-Printable |
| Compression | Gzip, Zlib, Deflate, Bzip2, LZMA (de/compress) |
| Cryptography (симметр.) | AES (ECB/CBC/CTR/GCM), XOR (single/multi-byte key, brute-force key length), RC4, ChaCha20 |
| Hashing | MD5, SHA-1/256/512, SHA-3, BLAKE2/3, CRC32, ssdeep (fuzzy) |
| Encoding форматов | JSON pretty/minify, XML pretty, MessagePack decode, Protobuf (без схемы — raw varint walk) |
| Бинарный анализ | Hex Viewer/Editor, PE/ELF/Mach-O header parse, Entropy graph (по чанкам), Strings extraction (ASCII/UTF-16/UTF-8) |
| Текст | Regex extract/replace, Diff (two-branch merge node), Case transforms, Unicode normalize |
| Сеть | PCAP parse (базовые L2-L4 поля), URL parse, User-Agent parse, JWT decode/verify |
| Auto-detect | Magic-bytes детектор формата, "Magic Wand" — эвристический подбор цепочки декодирования для неизвестного blob |

- FR-3.1: Каждая операция — реализация трейта `Transform` (см. Rust-документ). Ядро ничего не знает о конкретных операциях, только о трейте и реестре.
- FR-3.2: Операции с параметрами рендерят форму параметров автогенерируемую из JSON Schema, отдаваемой самой операцией через Tauri command `list_operations`.
- FR-3.3: Каждая операция обязана декларировать: детерминированность, максимальную стоимость по памяти (для стрим-планировщика), поддержку потокового (chunked) режима.

### 3.4 Time-Travel State (история)
- FR-4.1: История — не линейный undo/redo, а граф состояний (state DAG), изоморфный графу узлов, с возможностью прыгнуть в любую точку и создать новую ветку оттуда (аналог Git, не аналог Ctrl+Z).
- FR-4.2: Любой снапшот воспроизводим (reproducible): фиксируются входные байты (или ссылка на content-hash), версия операции, параметры.
- FR-4.3: Diff между двумя снапшотами доступен как view (byte-level diff, не только текстовый).

### 3.5 Файлы и потоковая обработка
- FR-5.1: Открытие файлов до 32 ГБ без блокировки UI и без полной загрузки в RAM.
- FR-5.2: Чтение чанками по 64 МБ в выделенных Rust-тредах (см. Performance Mandates); UI получает прогресс и частичный превью первых N КБ немедленно.
- FR-5.3: Операции, не поддерживающие chunked-режим (напр. многие crypto-blockmodes без потокового API), обязаны явно задекларировать это и UI обязан предупредить пользователя об оценке потребления памяти до запуска.
- FR-5.4: Экспорт результата — стриминговая запись на диск, без промежуточной сборки в один `Vec<u8>` в памяти, где это возможно.

### 3.6 Плагины
- FR-6.1: Плагин — WASM-модуль (WASI-подобный интерфейс) с манифестом (имя, версия, автор, запрошенные capabilities).
- FR-6.2: Плагин обязан быть подписан (Ed25519); неподписанные плагины загружаются только в explicit "Developer Mode" с визуальным предупреждением.
- FR-6.3: Плагин выполняется в изолированном runtime (Wasmtime) без доступа к файловой системе/сети, если явно не запрошено и не подтверждено пользователем per-permission (модель как в мобильных ОС).
- FR-6.4: Плагин регистрирует одну или несколько операций через тот же `Transform`-подобный интерфейс, сериализуемый через WIT (WASM Component Model).

### 3.7 Экспорт/интеграция
- FR-7.1: Экспорт recipe (графа) в переносимый JSON-формат (`.hexforge` файл) — включая версии операций для воспроизводимости на другой машине.
- FR-7.2: Экспорт в CyberChef-совместимый recipe JSON (миграционный мост) — best-effort маппинг операций 1:1 там, где семантика совпадает.
- FR-7.3: CLI-режим (`hexforge run recipe.hexforge --in file --out file`) на том же Rust-ядре, без GUI, для CI/скриптинга.

## 4. Нефункциональные требования

| ID | Требование |
|---|---|
| NFR-1 | Input-to-visual-feedback (Tti) < 16ms для любого UI-взаимодействия; операции >16ms обязаны быть async и не блокировать main/render thread |
| NFR-2 | Поддержка файлов до 32 ГБ без деградации (constant memory footprint относительно размера файла для потоковых операций) |
| NFR-3 | Холодный старт приложения < 400ms на reference hardware (M-серии Apple Silicon / современный x86_64) |
| NFR-4 | Zero known critical/high CVE в зависимостях на момент релиза (автоматизировано через `cargo audit` + `npm audit` в CI) |
| NFR-5 | Кроссплатформенность: macOS (arm64/x64), Windows (x64/arm64), Linux (x64, AppImage + deb) |
| NFR-6 | Полная функциональность offline; сеть используется только опционально (обновления, plugin registry) |
| NFR-7 | Accessibility: полная клавиатурная навигация (без палитры включительно), контраст WCAG AA в обеих темах |
| NFR-8 | Локализация: архитектурная готовность (i18n-ключи с первого дня), en/ru в MVP |
| NFR-9 | Плагин не может уронить хост-процесс: паника/OOM/infinite loop в WASM-модуле изолируются (fuel-limited execution, memory limits per instance) |
| NFR-10 | Все Tauri IPC-команды типизированы и валидируются по схеме на обеих сторонах моста (см. `05-IPC-CONTRACT`) |

## 5. Явно вне скоупа MVP
- Совместная работа в реальном времени (multi-user collaboration).
- Облачная синхронизация recipe (только локальный файл/экспорт в MVP).
- Marketplace плагинов с автообновлением (в MVP — локальная установка `.wasm` + манифест).
- Мобильные клиенты.

## 6. Метрики успеха
- Время от открытия файла 10 ГБ до первого байта превью: < 200ms.
- 95-й перцентиль времени отклика Command Palette (keypress → filtered list render): < 16ms при 500+ зарегистрированных командах.
- Ноль блокировок UI-потока дольше 16ms, зафиксированных в perf-профилировании эталонных сценариев (см. CI perf gate).
